# TASK: надёжный разбор заявок с AI

## Цель
Менеджер вводит текст заявки и получает тему и черновик ответа. Если AI ответил медленно, с ошибкой или некорректно, менеджер явно видит, что заявку нужно разобрать вручную, и на экране не остаётся черновик от прошлого запроса.

## Ограничения
- Node.js 20+, **никаких зависимостей**. Только встроенные модули и `node:test`.
- `mock-ai.mjs` **не меняем**.
- Код простой: никаких фреймворков, сборки и лишних абстракций.

## 1. API `POST /api/triage`

### Ввод
Тело — JSON-объект с полем `text`. После `trim()` в нём должна остаться непустая строка. Тело не больше 10 КБ.

### Контракт
| Сценарий | HTTP | Тело |
|---|---|---|
| Битый JSON, `null`, массив, примитив | 400 | `{"status":"invalid_input"}` |
| Нет `text` или `text` не строка | 400 | `{"status":"invalid_input"}` |
| `text` пустой или из одних пробелов | 400 | `{"status":"invalid_input"}` |
| Тело больше 10 КБ | 400 | `{"status":"invalid_input"}` |
| Модель ответила корректно | 200 | `{"status":"ready","topic":"…","draft":"…"}` |
| Модель не ответила за 300 мс (`[timeout]`) | 200 | `{"status":"manual_review","topic":null,"draft":null}` |
| Модель бросила ошибку (`[error]`) | 200 | то же |
| Ответ модели — не JSON (`[bad-json]`) | 200 | то же |
| Недопустимая тема (`[bad-topic]`) | 200 | то же |
| Пустой черновик (`[empty-draft]`) | 200 | то же |
| Непредвиденная ошибка сервера | 500 | `{"status":"server_error"}` |

### Проверка ответа AI (`checkModelOutput` в `server.mjs`)
Ответ модели — строка. Он корректен, только если выполнены все условия:
1. `JSON.parse` проходит без ошибки.
2. Результат — объект: не `null` и не массив.
3. `topic` входит в `["delivery", "pricing", "other"]`.
4. `draft` — строка, непустая после `trim()`.

В ответ API попадают **только** поля `status`, `topic` и `draft`. Остальные поля модели отбрасываются, и подменить `status` модель не может.

### Таймаут
- В `classify` передаётся `AbortSignal.timeout(300)`.
- Вызов оборачивается в `Promise.race` с этим же сигналом. Так ответ уложится в 300 мс, даже если модель проигнорирует отмену.

### Структура `server.mjs`
- Экспортирует сервер, чтобы его можно было импортировать в тесте.
- `listen` вызывается только при прямом запуске `node server.mjs`. Порт берётся из `PORT`, по умолчанию 3000.

## 2. Страница `index.html`
- На время запроса кнопка заблокирована, а прежний результат очищен.
- `ready`: показать тему с русской подписью (`delivery` → «Доставка», `pricing` → «Цена», `other` → «Другое») и черновик.
- `manual_review`: сообщение «AI не смог подготовить ответ. Разберите заявку вручную.», черновик пуст.
- 400: «Введите текст заявки.»
- Любая другая ошибка (500, сеть, не-JSON): «Сервис недоступен, попробуйте ещё раз.»
- Вывод только через `textContent`, без `innerHTML`.

## 3. Тесты (`server.test.mjs`, `node:test` + `fetch`)
Сервер поднимается на порту 0 и закрывается после тестов.
- Каждая из пяти меток сбоя → 200 `manual_review`, `topic` и `draft` равны `null`.
- `[timeout]` отвечает быстрее 1000 мс: доказательство, что работает лимит, а не задержка имитатора.
- Невалидный ввод (по таблице выше) → 400 `invalid_input`.
- Обычный текст → 200 `ready`, тема и черновик корректны.

## 4. Запуск
- `package.json` без зависимостей, скрипты `"start": "node server.mjs"` и `"test": "node --test"`.
- В README добавить раздел «Тесты» с командами `npm test` и `node --test`.

## 5. Ручная проверка
- `npm test` проходит.
- curl по каждой метке и по невалидному вводу.
- В браузере сначала успешная заявка, затем `[timeout]`: черновик исчезает, видно сообщение для ручного разбора.
